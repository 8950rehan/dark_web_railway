# Dark Web Monitoring — PostgreSQL Schema

This repository implements the three tables described in the supplied Database Schema Report:

- `users` — authentication metadata, role, MFA flag, and account status
- `source` — monitored-source registry, including a required legal authorization reference
- `crawl_job` — crawl attempts, lifecycle state, metrics, and source relationship

## Files

- `schema.sql` — creates the tables, constraints, and indexes
- `seed.sql` — optional demo rows for testing
- `verify.sql` — verifies table existence and joins all three tables
- `.env.example` — connection URL placeholder; contains no credentials

## Option A — Host PostgreSQL on Railway

1. Sign in to [Railway](https://railway.app/) and create a new project.
2. Choose **Add Service** → **Database** → **PostgreSQL**.
3. Open the PostgreSQL service and find its connection details in **Connect** or **Variables**. Copy the private/internal or public connection URL as appropriate for where you are connecting from. Treat it like a password.
4. Install PostgreSQL client tools (`psql`) on your computer if needed.
5. Run the schema against the Railway database. Replace `<RAILWAY_DATABASE_URL>` with the connection URL you copied:

   ```bash
   psql "<RAILWAY_DATABASE_URL>" -v ON_ERROR_STOP=1 -f schema.sql
   ```

6. (Optional) Add demo rows:

   ```bash
   psql "<RAILWAY_DATABASE_URL>" -v ON_ERROR_STOP=1 -f seed.sql
   ```

7. Verify the deployment:

   ```bash
   psql "<RAILWAY_DATABASE_URL>" -v ON_ERROR_STOP=1 -f verify.sql
   ```

   The verification query should show the three tables and, after running `seed.sql`, one joined demo row.

**Important:** creating a Railway database service does not necessarily execute these SQL files automatically. Run `schema.sql` against the provisioned database as shown above.

## Option B — Run locally with PostgreSQL

Create a database, then execute:

```bash
createdb darkweb_monitoring
psql "postgresql://localhost/darkweb_monitoring" -v ON_ERROR_STOP=1 -f schema.sql
psql "postgresql://localhost/darkweb_monitoring" -v ON_ERROR_STOP=1 -f seed.sql
psql "postgresql://localhost/darkweb_monitoring" -v ON_ERROR_STOP=1 -f verify.sql
```

## Schema relationships

```text
users
  └── usr_id (PK)
       ▲
       │ source.created_by (FK)
source
  └── source_id (PK)
       ▲
       │ crawl_job.source_id (FK)
crawl_job
  └── job_id (PK)
```

A user registers a source; each crawl job targets a registered source. The required `auth_ref` field records the authorization reference for each source.

## Security notes

- `password_hash` must contain a password hash generated by a suitable password-hashing algorithm; never store plaintext passwords. The demo value is only a placeholder.
- Use Railway's private connection URL for services inside the same Railway project when available. Do not publish database credentials in source control, screenshots, or reports.
- Only register sources for which you have documented authorization. Use a test or staging database for demo data.
- The schema creates metadata tables only; it does not implement a crawler, web API, or login flow.
- The database has not been deployed by this ZIP itself. Deployment requires signing in to Railway and creating/provisioning the database in your account.
